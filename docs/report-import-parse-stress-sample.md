# 报表导入解析 XLSX 压测样例

生成文件：`docs/report-import-parse-stress-sample.xlsx`

## 导入模板

- 第一列：`report_code`。
- 后续列：`sql_1` 至 `sql_120`。
- 每行代表一个报表；空 SQL 单元格保留为空，导入逻辑会跳过。
- 建议导入参数：`fileType=XLSX`，`reportCodeField=report_code`，`datasourceCode=hetu_main`，`stage=PROD`，`priority=high`。

## 样例规模

- 报表数：`600`。
- SQL 总数：`2749`。
- 每报表 SQL 数：最少 `3`，最多 `30`；保留 `sql_1..sql_120` 模板列。
- 复杂度分布：LOW `549`，MEDIUM `1100`，HIGH `1100`。
- 中高复杂度占比：`80.03%`。
- 最短 SQL 行数：`22`；中高复杂度最短行数：`130`。

说明：600 个报表在 3-120 的约束下不可能做到“SQL 数量全局两两不同”，因为可用数量只有 118 种。本样例让报表 SQL 数在 `3..30` 内变化，仍满足不超过 120，并保留 120 个 SQL 列以符合导入模板。此前按 3..120 全覆盖生成的 9184 条长 SQL 样例会触发当前后端导入阶段 `Java heap space`，原因是导入实现会把整行所有长 SQL 拼入每条展开记录的 `rawLine`。

## 垃圾 SQL 定义

本样例中的“垃圾 SQL”全部是语法正确、可导入的 `SELECT` / `WITH SELECT` 查询，模拟 BI 拖拉拽或低代码平台生成的低质量 SQL；不包含格式错误、语法错误、空白 SQL、纯注释 SQL、DML、DDL 或危险执行语句。

## 场景覆盖

1. `SELECT_STAR_WIDE_SCAN`：SELECT * / r.* wide projection from BI drag-and-drop output。
2. `WIDE_DUPLICATED_PROJECTION`：Dozens of repeated dimensional and metric projections。
3. `MISSING_PARTITION_FILTER`：Large fact scan without an effective partition predicate。
4. `FUNCTION_ON_PARTITION_FILTER`：Partition/date column wrapped by a function。
5. `IMPLICIT_DATE_CAST`：String/numeric date comparison that forces implicit cast。
6. `STRING_DATE_RANGE_COMPARE`：Date range kept as strings by low-code builder。
7. `LEADING_WILDCARD_LIKE`：Leading wildcard LIKE predicate。
8. `OR_PREDICATE_CHAIN`：Long OR chain instead of selective predicate normalization。
9. `LOW_SELECTIVITY_FILTERS`：Low-selectivity status/channel filters。
10. `LARGE_IN_LIST`：Very large IN list generated by checkbox filters。
11. `NOT_IN_NULL_SEMANTICS`：NOT IN predicate with BI default null-sensitive semantics。
12. `DISTINCT_OVERUSE`：DISTINCT used to hide join duplication。
13. `MANY_GROUP_BY_COLUMNS`：Too many group-by dimensions。
14. `AGGREGATE_THEN_FULL_SORT`：Aggregate followed by full ORDER BY without pruning。
15. `FULL_ORDER_BY_NO_LIMIT`：Full sort without LIMIT。
16. `NESTED_SUBQUERY_STACK`：Deep nested subquery stack。
17. `DERIVED_TABLE_WRAP_STACK`：Derived table layers created by visual query builder。
18. `CTE_OVERUSE`：Many CTE stages with small transformations。
19. `REPEATED_SUBQUERY_TEXT`：Same subquery written repeatedly instead of reused。
20. `COMMA_JOIN_CARTESIAN_RISK`：Comma join style with weak join predicates。
21. `LEFT_JOIN_FILTER_IN_WHERE`：LEFT JOIN right-table filters in WHERE。
22. `JOIN_KEY_CAST`：Join keys wrapped by CAST。
23. `JOIN_CONDITION_TOO_WIDE`：Over-wide join condition with many dimensions。
24. `FACT_JOIN_BEFORE_FILTER`：Large fact table joined before filtering。
25. `WIDE_WINDOW_PARTITION`：Window function partitioned by many dimensions。
26. `WINDOW_ORDER_TOO_WIDE`：Window function sorted by too many fields。
27. `LONG_CASE_MAPPING`：Long CASE mapping generated from BI labels。
28. `COALESCE_WRAP_OVERUSE`：Repeated COALESCE/NVL style wrapping。
29. `ALIAS_AND_EXPRESSION_NOISE`：Expression alias and generated-field noise。
30. `REDUNDANT_PARENTHESES`：Redundant parentheses around expressions。
31. `REPEATED_CAST`：Repeated CAST on the same field。
32. `CONSTANT_COLUMN_NOISE`：Many constant columns generated for report headers。
33. `REPEATED_LOGICAL_OBJECT_SCAN`：Repeated scans of the same logical object。
34. `JSON_REPEAT_PARSE`：Repeated JSON path extraction in projection/filter。
35. `DETAIL_SQL_DOES_PIVOT`：Detail-level SQL doing report pivot logic。
