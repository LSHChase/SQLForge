## 阶段质量门禁（Phase Gate）

### R-116 阶段入口验证

- 触发时机：新阶段启动前
- 检查清单：
  1. 上一阶段所有阻塞 Issue 状态 = 已关闭
  2. 规则库已追加本阶段新规则
  3. ADR 状态与本阶段技术决策匹配
  4. 执行计划文档已创建/更新
- 通过标准：4 项全部通过
- 失败处置：禁止进入下一阶段，返回未就绪项清单
- 关联规则：`R-007`, `R-012`

### R-117 阶段交付质量门禁

- 触发时机：阶段结项时
- `repo-closed` 主路径检查清单：
  1. 该阶段定义的 100% 仓库内检查项已执行，且不得移除 smoke / runtime gate、build/test/lint、db-script、coverage 等主路径证据
  2. 单元覆盖率达到阈值（阶段 0：80%，阶段 1+：85%），可通过 `bash scripts/run-coverage.sh --phase phase0|phase1plus` 执行
  3. 所有服务 `mvn clean install` 通过
  4. 前端 `npm run build` + `npm run lint` 通过
  5. 数据库脚本可执行
  6. `lint-repository-knowledge.js` 通过
- `environment-backed` 增强项（默认非阻断）：
  1. SonarQube 扫描保留为 fallback，可通过 `bash scripts/run-sonar.sh` 或 `bash scripts/run-sonar.sh --require-config` 执行
  2. 真实 Kafka runtime gate 保留为 fallback，可通过 `bash scripts/run-phase-gates.sh --gate compliance --run-real-kafka-gate` 或独立 workflow 执行
  3. 外部测试环境 CI/CD 只能作为补充环境证据；若缺少仓库内 smoke / runtime gate，不得替代 `repo-closed` 主路径
- 通过标准：`repo-closed` 主路径全部通过；`environment-backed` 增强项仅在环境已配置或显式要求时记录 pass/fail，否则可记录为 skipped，默认不阻断阶段 closeout
- 失败处置：主路径失败则标记阶段状态为“待修复”，输出阻塞清单；增强项失败则记录 residual risk / 恢复项，不得倒推出仓库主线未闭环
- 关联规则：`R-040`, `R-012`

### R-118 渐进等保验证

- 触发时机：每阶段结项时
- 检查清单：重新验证 `R-111` 至 `R-115` 对应的实现，包括：
  1. 身份鉴别入口未被删除或绕过
  2. 访问控制逻辑未被弱化
  3. 审计日志表结构与保留策略未变更
  4. 敏感字段加密机制未退化
  5. 备份策略提示未删除
- 通过标准：5 项全部通过
- 失败处置：标记为合规退化，必须修复后重新验证
- 关联规则：`R-111`, `R-112`, `R-113`, `R-114`, `R-115`

## 任务级即时验证（Task Validation）

### R-119 代码生成即时编译

- 触发时机：每个 Task 代码生成后
- 检查清单：
  1. 后端执行 `mvn clean compile` 或前端执行 `npm run build`
  2. 无编译错误
  3. 无新增 deprecation warning（除非 ADR 允许）
- 通过标准：3 项全部通过
- 失败处置：不进入下一 Task，必须修复编译错误
- 关联规则：`R-021`, `R-022`

### R-120 分层结构回归

- 触发时机：任何涉及包结构调整的 Task 后
- 检查清单：
  1. 目录树符合“领域目录 + 分层子目录”
  2. 无顶层扁平 `controller/service` 目录（`QV-001` 复现检查）
  3. 领域层无 Spring 注解
  4. 包名与目录结构一致
- 通过标准：4 项全部通过
- 失败处置：立即重构，禁止提交
- 关联规则：`R-021`, `R-022`, `QV-001`

### R-121 接口契约符合度

- 触发时机：新增/修改接口后
- 检查清单：
  1. 输入字段与契约文档一致（名称/类型/必填/长度）
  2. 输出字段与契约文档一致
  3. 边界条件处理（空值/超时/超长/越界）
  4. 错误码在 `ErrorCodeConstants` 中定义
- 通过标准：4 项全部通过
- 失败处置：更新契约文档或修改代码，保持双向一致
- 关联规则：`R-041`, `R-057`

### R-122 MyBatis XML验证

- 触发时机：涉及数据库操作的 Task 后
- 检查清单：
  1. SQL 写在 XML 中，非注解
  2. Mapper 接口与 XML `namespace` 一致
  3. 参数使用 `#{}` 预编译，禁止 `${}` 拼接（防注入）
  4. 复杂查询有 EXPLAIN 计划注释
- 通过标准：4 项全部通过
- 失败处置：重构为 XML 方式
- 关联规则：`R-065`, `R-045`

### R-123 流程节点日志验证

- 触发时机：涉及业务逻辑的 Task 后
- 检查清单：
  1. 主要节点（入口/出口/异常/状态变更）有日志
  2. 日志包含操作类型、实体标识、耗时、结果状态
  3. 无敏感信息明文打印
- 通过标准：抽查通过
- 失败处置：补充日志或脱敏处理
- 关联规则：`R-060`, `R-064`, `R-039`

### R-124 前端三件套验证

- 触发时机：前端代码修改后
- 检查清单：
  1. `npm install` 通过
  2. `npm run build` 通过
  3. `npm run lint` 通过（0 error）
  4. 路由/国际化/主题变量文件未被误删
- 通过标准：4 项全部通过
- 失败处置：修复后重新 build
- 关联规则：`R-088`, `R-089`, `R-090`, `R-091`, `R-092`, `R-093`, `R-094`, `R-095`, `R-096`, `R-097`, `R-098`

## 修复回归验证（Fix Regression）

### R-125 阻塞问题修复回归

- 触发时机：阻塞问题（如 `QV-xxx`）修复后
- 检查清单：
  1. 重新执行该问题的完整验证流程
  2. 原验证报告中的检查项 100% 通过
  3. 修复未引入新问题（Git diff 检查）
  4. 更新验证报告状态为“已修复”
- 通过标准：4 项全部通过
- 失败处置：继续修复，禁止进入下一阶段
- 关联规则：`R-040`, `R-128`

### R-126 跨服务影响验证

- 触发时机：修改 common 模块或接口契约后
- 检查清单：
  1. 所有消费该 common 的服务编译通过
  2. 接口变更方已通知消费方
  3. 契约测试用例更新并通过
- 通过标准：3 项全部通过
- 失败处置：协调消费方同步修改或保持向后兼容
- 关联规则：`R-020`, `R-068`

### R-127 性能基线回归

- 触发时机：涉及解析/路由/执行的优化或重构后
- 检查清单：
  1. JMH 基准测试通过
  2. P99 延迟不超过该阶段基线（阶段 1：50ms）
  3. 内存占用不超过基线（阶段 1：2GB）
- 通过标准：3 项全部通过
- 失败处置：回滚或优化，禁止合并
- 关联规则：`R-003`

## 环境与配置验证（Environment）

### R-128 多环境配置隔离

- 触发时机：修改 `application-*.yml` 后
- 检查清单：
  1. `dev/test/prod` 三个文件存在且非空
  2. 各环境数据库连接指向不同实例
  3. 生产配置 `auth.enabled=true`，`dev` 可为 `false` 但必须有注释说明
  4. 敏感配置（密码）使用环境变量或加密，禁止明文
- 通过标准：4 项全部通过
- 失败处置：重构配置，敏感信息轮换
- 关联规则：`R-066`, `R-114`

### R-129 数据库脚本同步

- 触发时机：Entity 或表结构变更后
- 检查清单：
  1. 检查 `init-schema.sql` 是否需要更新
  2. 若已发布环境，提供增量脚本（`V{version}__desc.sql`）
  3. 脚本在本地 MySQL 可执行
  4. 若目标库为 MySQL / TDSQL，确认本次 DDL 未新增物理外键约束
  5. 更新 Entity 与脚本的映射文档
- 通过标准：5 项全部通过
- 失败处置：补充脚本，禁止代码与库结构不一致
- 关联规则：`R-106`, `R-107`, `R-169`

### R-130 容器编排验证

- 触发时机：修改 `docker-compose.yml` 后
- 检查清单：
  1. `docker-compose config` 语法检查通过
  2. `docker-compose up -d` 所有服务 Healthy
  3. 端口无冲突
  4. 数据卷持久化配置正确
- 通过标准：4 项全部通过
- 失败处置：修复编排文件
- 关联规则：`R-076`

## 规则库与文档自维护（Rule Maintenance）

### R-131 规则追加完整性

- 触发时机：每次新增规则后
- 检查清单：
  1. 规则 ID 连续，无跳号
  2. `codex-rules.md` 已追加
  3. `human-constraint-history.md` 已追加
  4. `lint-repository-knowledge.js` 可检查到新规则
- 通过标准：4 项全部通过
- 失败处置：补全规则，修复脚本
- 关联规则：`R-009`, `R-104`

### R-132 ADR同步验证

- 触发时机：新增/变更 ADR 后
- 检查清单：
  1. `docs/adr/README.md` 索引已更新
  2. 编号连续，无冲突
  3. 关联代码有 ADR 编号注释
  4. Superseded 的 ADR 已链接新 ADR
- 通过标准：4 项全部通过
- 失败处置：补全 ADR 索引与链接
- 关联规则：`R-102`, `R-103`

### R-133 文档同步验证

- 触发时机：代码变更涉及接口/架构/配置后
- 检查清单：
  1. 接口契约文档同步更新
  2. 架构图（C4）描述同步更新；当前默认更新落点为 `docs/architecture/c4-overview.md`，独立图片工件不是强制项，文字版 C4 说明即可作为权威工件
  3. 使用手册（如新增配置项）同步更新
  4. README 索引无死链
- 通过标准：4 项全部通过
- 失败处置：同步更新文档，禁止文档与代码不一致；若架构变化未同步 `c4-overview.md` 或等价权威 C4 说明，则视为未通过
- 关联规则：`R-006`, `R-048`

### R-134 上下文收缩与清理验证

- 触发时机：任务进入 closeout、或完成单任务 commit 准备切换到下一任务前
- 检查清单：
  1. 已完成上下文收缩：权威来源中可见已完成范围、验证命令与结果、剩余风险/未决项、下一步与任务状态
  2. 实现阶段上下文已清理（无残留的文件句柄、ThreadLocal、缓存；不把上一任务局部推理直接沿用到下一任务）
  3. 仅保留后续切换所需的结论性信息：任务结论、文件清单、规则引用、ADR 引用、权威台账回写记录
  4. 验证无敏感信息残留于上下文中
- 通过标准：4 项全部通过
- 失败处置：强制重新清理
- 关联规则：`R-001`, `R-168`

### R-135 验证规则自指

  2. 本规则不可删除修改（`R-003` 扩展）
  3. 后续所有验证行为必须引用本规则子集

- 失败处置：不可失败（元规则）
- 关联规则：`R-003`

## 自动触发验证规则（R-136 至 R-143）

### R-136 Task交付自动验证

- 触发时机：Codex 标记任意 Task 为“已完成”时
- 执行动作：
  1. 必须自动执行以下验证子集（按 Task 类型选择适用项）：
     - 所有 Task：`R-119` 代码编译验证
     - 涉及包结构调整：`R-120` 分层回归
     - 涉及接口变更：`R-121` 契约符合度
     - 涉及业务逻辑：`R-123` 流程日志验证
     - 涉及前端代码：`R-124` 前端三件套验证
     - 涉及 Entity/表结构：`R-129` 数据库脚本同步
- 输出要求：必须输出《Task交付验证报告》，含规则 ID、检查结果、证据路径、是否阻塞下一 Task
- 关联规则：`R-119`, `R-120`, `R-121`, `R-122`, `R-123`, `R-124`, `R-129`, `R-134`

### R-137 Story交付自动验证

- 触发时机：Codex 完成 Story 最后一个 Task 且 `R-136` 全部通过后
- 执行动作：必须自动执行 `R-117` 阶段交付门禁的 Story 子集 + `R-126` 跨服务影响 + `R-133` 文档同步
- 输出要求：输出《Story交付验证报告》，含 Task 汇总、回归测试结果、是否可进入下一 Story
- 关联规则：`R-117`, `R-126`, `R-133`

### R-138 阻塞问题修复自动回归

- 触发时机：Codex 检测到提交信息含 `fix(qv-` 或 Issue 状态变更为“已修复”
- 执行动作：必须自动执行 `R-125` 完整流程：重新执行原验证报告全部检查项 + Git diff 检查 + 更新验证报告状态为“已修复”
- 输出要求：输出《阻塞问题回归报告》，原验证报告追加“已修复/验证通过”状态
- 关联规则：`R-125`

### R-139 阶段切换自动门禁

- 触发时机：Codex 检测到阶段计划文件被标记为“待验收”或人类输入含“进入阶段 X”
- 执行动作：必须自动执行 `R-116` 阶段入口验证 + `R-117` 阶段交付门禁 + `R-118` 渐进等保
- 输出要求：全部通过输出“阶段 X 已解锁”；任一失败输出“阶段 X 已阻塞”及未就绪清单
- 关联规则：`R-116`, `R-117`, `R-118`

### R-140 验证行为日志固化

- 触发时机：每次 `R-136` 至 `R-139` 执行后
- 执行动作：必须将验证报告追加写入 `docs/quality/validation-log.md`（append-only）
- 格式：时间戳 | 触发规则 | 验证规则子集 | 结果 | 证据路径
- 禁止删除历史验证记录
- 关联规则：`R-009`, `R-038`

### R-141 验证失败自动阻断

- 触发时机：`R-136` 至 `R-139` 任一验证失败时
- 执行动作：Codex 必须停止后续所有代码生成任务；输出失败规则 ID、影响范围、修复建议、预计修复工时；禁止自动修复后偷偷继续，必须等待人类确认
- 输出要求：《验证阻断通知书》
- 关联规则：`R-049`, `R-050`

### R-142 验证规则版本自指

- 触发时机：本规则追加后，每次 Codex 对话开始时
- 执行动作：自检当前规则库最大 ID 是否至少为 `R-154`，`validation-rules.md` 是否存在且非空
- 失败处置：若缺失 `R-116` 至 `R-154`，立即告警“规则库版本过低，缺少自动验证规则”并中止任务
- 关联规则：`R-003`, `R-135`

### R-143 人类豁免通道
