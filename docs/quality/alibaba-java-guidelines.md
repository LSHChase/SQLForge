# SQLForge Alibaba Java Guidelines

本文件将阿里 Java 代码规范固化为 SQLForge 的仓库内落地版本，作为 Java 8 + Spring Boot 2.x + MyBatis XML 技术栈的默认编码参考。

## 规范来源

- 官方项目：`alibaba/p3c`
- 公开稳定版本：`黄山版`
- 官方发布日期：`2022-02-03`
- 原始资料归档目录：`docs/references/raw-requirements/alibaba-java-guidelines/`
- 当前适用范围：`sqlforge-common/`、`governance-service/` 及后续 Java 服务模块

## 落地方式

- 强制执行：通过规则、CI、Maven 扫描和代码评审共同约束。
- 推荐执行：作为默认实现方式，若偏离需给出理由。
- 人工评审：不适合由静态工具可靠判断的工程约束，由评审和设计文档补位。

## 强制执行

### 命名与常量

- 包名、类名、方法名、参数名、成员变量名必须语义明确，避免拼音缩写和无意义简称。
- 常量统一使用 `static final` 并采用全大写下划线命名。
- 禁止同一职责出现语义重复但拼写不同的命名。

### 分层与职责

- `Controller` 只负责 HTTP 边界、参数接收、结果返回和轻量编排。
- `Service` / `ApplicationService` 负责应用层编排，不承载持久化细节。
- `Domain` 负责领域规则，保持无 Spring 注解的边界。
- `Repository` / `Mapper` 只负责数据访问，MyBatis 复杂 SQL 继续落在 XML。
- `DTO`、`VO`、`Entity` 不能混用职责，也不能跨层随意透传。

### 异常与日志

- 禁止吞异常、重复包装无意义异常或直接抛出裸 `Exception` 作为业务表达。
- 错误返回必须复用统一错误码和统一响应结构。
- 日志必须保留业务定位字段，禁止打印密码、令牌、密钥等敏感信息。
- 记录异常时优先保留上下文和链路信息，避免只有一段不可定位的提示文本。

### 集合、空值与防御式编程

- 集合判空、字符串判空、上下文值读取必须显式处理空值路径。
- 对外部输入、Header、配置项、数据库结果保持防御式编程，不假定必然存在。
- `equals` / `hashCode`、Map Key、Set 元素等基础对象语义必须保持一致。

### 单元测试

- 新增应用层、拦截器、转换器和关键领域逻辑时应补充单元测试或切片测试。
- 测试名称必须表达行为和预期结果，不写无语义缩写。
- Mock 只覆盖边界依赖，不绕过待验证逻辑本身。

## 推荐执行

- 复用现有公共异常、常量、上下文和日志设施，不新增同类散落实现。
- 优先返回稳定、可读、具领域语义的对象，而不是裸 `Map` 或弱类型结构。
- 方法保持单一职责，避免在 Controller 中叠加过多分支判断。
- 优先通过转换器隔离对象形态差异，避免跨层直接复用同一数据结构。

## 人工评审

- 并发模型、线程池和异步执行边界是否符合阿里并发规约。
- 批量数据处理、缓存、事务与幂等设计是否存在隐性风险。
- SQL、索引和 ORM 映射是否存在性能或维护性问题。
- 文档、代码和架构边界是否保持一致。

## 与现有规则映射

- `R-021`、`R-022`：继续保持后端强制分层和领域目录结构。
- `R-065`：MyBatis XML 仍是数据访问默认方式。
- `R-066`：配置差异通过多环境配置管理，不在代码中硬编码。
- `R-068`：跨域通过 Service DTO 交互，禁止 Entity 直接跨服务传输。
- `R-145` 至 `R-150`：阿里 Java 规范治理专用规则。

## 工具执行

- Maven：`mvn validate`
- PMD：`mvn pmd:pmd`
- Checkstyle：`mvn checkstyle:check`
- 结果解释：
  - 阻塞项：必须在交付前解决
  - 高风险项：需要在本轮或紧邻轮次解决
  - 一般项：进入存量治理清单
