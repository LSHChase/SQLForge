# Temporary / In-Memory / Static Substitute Audit

Task: `USER-CN-AUDIT-TEMP-INMEMORY-STATIC-20260525`

Date: 2026-05-25

Scope: repository-side read-only audit of in-memory implementations, static or constant result paths, mock/simulated/synthetic/fallback/placeholder substitutes, and related documentation boundaries. This audit does not change business code.

## Method

- Ran strict foreman preflight for `USER-CN-AUDIT-TEMP-INMEMORY-STATIC-20260525`.
- Searched source, scripts, SQL, frontend, and docs with broad markers: `in-memory`, `inmemory`, `mock`, `simulated`, `synthetic`, `fallback`, `placeholder`, `hardcoded`, `static result`, and related variants.
- Excluded generated/build outputs such as `target/`, `node_modules/`, `dist/`, `dist-portable/`, and `build/` for the primary source scan.
- Reviewed high-risk hits in context instead of treating every helper named `fallback` as temporary behavior.

## Executive Summary

The repository has removed most earlier default in-memory persistence from governance and the main sql-optimization carriers, but several temporary substitute paths remain by design. The highest-risk finding is that `report_batch` and `report_batch_item` have MyBatis repositories and schema, but the active Spring beans are still unconditional `@Primary` in-memory repositories. The other production-facing substitutes are mostly explicit and evidence-labeled: report SQL mock fallback, structure-parse fallback profiles, query execution deterministic simulation for non-live routes, benchmark synthetic workload backfill, process-local result cache, and governance-side simulated notification / enforcement / health status.

The rewrite recommendation core is intentionally static in several layers. It is not currently claiming production auto-apply: the code and docs consistently mark `NO_SQL_EXECUTION`, static cost, surrogate RelToSql, and manual review boundaries. That makes it an architectural gap rather than an accidental hidden substitute.

## Lower-Risk / Expected Fixtures

- `governance` in-memory repositories under `governance.infrastructure.repository` are not Spring `@Repository` beans; MyBatis repositories are the active default. `docs/architecture/persistence.md` also records that the original in-memory repositories are test fixtures rather than default beans.
- Governance `InMemoryMessageBus` is always constructible but only used by `MockMessageProducer` / `MockMessageConsumer` when `messaging.mode=MOCK`. Dev and test resource profiles use `DATABASE`; production docs require `KAFKA`.
- `sql-optimization` in-memory repositories for parse history, parse batch, recommendation, dispatch event, rewrite trial, candidates, and rewrite records are mostly gated by `repository=test` or explicit `queues.mode=local-placeholder`. Report batch is covered by `TEMP-AUDIT-001`; queue-mode `matchIfMissing=true` repositories are covered by `TEMP-AUDIT-012`.
- `benchmark-engine` `InMemoryBenchmarkTaskRepository` is gated by `benchmark-engine.queues.mode=local-placeholder`; main application config sets `database-worker`, while test config uses `local-placeholder`. The `matchIfMissing=true` annotation is tracked under `TEMP-AUDIT-012`.
- Smoke scripts and contract checks intentionally use mock servers or synthetic payloads, for example `scripts/mock-hetu-server.py`, frontend/portable mock backends, and recommendation-page synthetic contract fixtures. These are validation fixtures, not production code paths.

## Recommended Task Pack

1. `sql-optimization` report batch persistence hardening: condition or remove the in-memory `@Primary` repositories, verify `report_batch` / `report_batch_item` MyBatis selection, and add restart/persistence regression coverage.
2. Report SQL fallback hardening: add fail-closed policy for non-dev profiles, require explicit approval to parse/rewrite `MOCK_FALLBACK` report SQL, and expose fallback metrics.
3. Static fallback gating: prevent `HEURISTIC_FALLBACK`, `ADVANCED_STRUCTURE_PROFILE_FALLBACK`, `DB_VIEW_CATALOG_FALLBACK`, and `STATIC_PARSE` results from being rendered or consumed as live AST/catalog/proof evidence.
4. Runtime evidence separation: add UI/API guardrails so `SIMULATED`, `SYNTHETIC_ONLY`, `SYNTHETIC_BACKFILL`, `STATIC_PARSE`, `STATIC_ABSTRACT_COST`, and governance `SIMULATED_*` statuses cannot be rendered as live execution or external-integration evidence.
5. Production cache and repository profile gates: require Redis/provider-native cache and database-worker repositories in shared environments, or emit blocking startup diagnostics for `IN_MEMORY` / local-placeholder selections.
6. Static rewrite upgrade path: continue real planner/prover/execution evidence tasks before expanding auto-apply semantics.
