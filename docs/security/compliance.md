# Security Compliance

本文件落实等保 2.0 三级相关基线，覆盖 `R-111` 至 `R-115`，并作为后续服务实现、审计设计和运维验收的依据。

## R-111 身份鉴别

### 控制目标

所有受保护操作都必须由后端进行身份校验，前端不得绕过；核心引擎文档不再定义管理员 / 普通用户这类产品角色分层。

### 实施要求

- 所有 HTTP/API 请求必须携带可验证身份凭证。
- 后端必须在 controller 入站前后完成身份解析与受控访问上下文建立。
- 高风险配置或执行动作必须具备更严格的后端校验和执行留痕。
- 未认证或认证失败请求必须返回明确 JSON 错误。

### 验证点

- 未登录请求无法访问任何受保护资源。
- 缺失身份上下文的请求无法访问受保护接口。
- 认证失败与越界访问行为都被记录。

## R-112 访问控制

### 控制目标

基于租户 ID 进行数据隔离，SQL 执行时必须校验租户对目标数据源的访问范围，禁止跨范围查询。

### 实施要求

- 所有核心请求必须显式携带租户上下文。
- 数据源、查询任务、审计记录和导出记录都必须绑定租户 ID。
- 路由、执行、导出、压测等动作都要重新校验租户与数据源范围。
- 默认拒绝缺失访问范围的请求，不允许隐式放行。

### 验证点

- 跨租户访问请求被拒绝。
- 已移出访问范围的账号无法继续读取目标数据源。
- 数据隔离策略在接口测试和集成测试中可验证。

## R-113 安全审计

### 控制目标

所有 SQL 操作、登录登出和访问范围变更必须记录审计日志，日志保留不少于 180 天，且不可修改删除。

### 实施要求

- 审计日志至少记录时间、租户、用户、操作类型、目标对象、结果状态、耗时和链路 ID。
- SQL 原文、密码、Token 等敏感内容必须脱敏或加密后再记录。
- 审计日志建议双写本地持久化与消息链路，以支持补偿和归档。
- 审计日志表应独立备份并限制写后改删。

### 验证点

- 登录、登出、访问范围变更、查询执行都存在对应审计记录。
- 审计日志保留策略不少于 180 天。
- 审计记录不可由业务接口直接删除或修改。

## R-114 加密存储

### 控制目标

数据库密码、API 密钥等敏感配置必须使用 AES-256 或国密 SM4 加密存储，禁止明文落库。

### 实施要求

- 敏感配置在进入数据库前必须加密。
- 配置文件中不得硬编码真实密钥或密码。
- 日志、异常栈、导出文件中不得出现明文敏感数据。
- 密钥管理要与业务数据分离，可接入独立密钥服务或统一配置中心。

当前实现基线：

- `sqlforge-shared` 已提供共享 AES-256 GCM 密文 envelope 能力，当前 envelope 结构包含 `algorithm`、`keyId` 与随机 IV。
- `governance` 已提供 `GovernanceProtectedPersistenceService`，对以下写入点执行统一保护：
  - `config_snapshot.snapshot_payload`
  - `execution_result.result_payload`
  - `query_history.query_context`
  - `export_record.export_options`
  - `audit_log.request_params`
  - `audit_log.response_summary`
  - `system_config` 的密码 / token / key 类配置
- `system_config` 中命中敏感键名时，原值不再进入 `config_value`，而是写入 `value_ciphertext` 并保留 `value_mask/encryption_algorithm/encryption_key_id`
- 日志层继续保留 `password|token|secret` 模式掩码，持久化层再执行一次结构化脱敏/加密

### 验证点

- 数据库中不存在明文密码、Token、密钥。
- 日志中不存在敏感信息泄漏。
- 敏感字段在实体、DTO、VO 与 SQL 中都有明确处理策略。

## R-115 备份恢复

### 控制目标

MySQL 必须配置主从复制与定期全量备份，满足 `RPO < 1小时`、`RTO < 4小时`，且备份数据必须加密存储。

### 实施要求

- 生产环境采用主从或等效高可用方案。
- 备份至少包含全量备份、必要的增量或 binlog 策略。
- 审计日志和核心元数据应纳入优先恢复清单。
- 备份介质、对象存储或归档仓必须启用加密。
- 必须定期演练恢复流程并记录结果。

### 验证点

- 有明确的备份频率、保留周期和恢复责任人。
- 备份恢复演练结果可追溯。
- 审计与元数据服务可在目标窗口内恢复。

## 合规交付清单

- 身份鉴别与受控访问说明
- 租户隔离与访问控制说明
- 审计日志表与归档策略
- 敏感字段加密存储策略
- 备份恢复策略与演练记录
