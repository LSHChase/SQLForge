# ADR-009: 数据保留与销毁策略（等保合规）

- Status: Accepted
- Date: 2026-04-19
- Deciders: Human Architect, Codex Implementation Lead
- Technical Story: `Phase-D / 合规与数据治理`
- Tags: retention, audit, compliance

## Context

项目需要长期保存查询历史、结果证据、导出记录和审计日志，同时满足等保要求和恢复要求。规则中既要求历史默认永久保留，也要求完成结果作为不可变证据，且审计日志保留不少于 180 天。

## Decision Drivers

- 查询治理与审计都依赖长期历史
- 等保要求审计日志保留不少于 180 天
- 结果作为证据不能被重写
- 数据增长需要靠观测、分页、过滤、归档而不是随意删数

## Considered Options

1. 默认短期保留，周期性清理
2. 默认长期保留，按冷热分层、归档和权限控制治理
3. 把历史完全外包给对象存储

## Decision

选择“长期保留 + 冷热分层 + 受控销毁”的策略：

- 查询历史、导出、审计和关键结果默认长期保留
- 审计日志至少保留 180 天，不允许通过业务接口修改或删除
- 结果主体视为不可变证据，只允许标签、注释、归档、软删除类元数据控制
- 销毁只针对符合法规、策略或归档条件的数据，并需审批、审计和可追溯记录

## Consequences

### Positive

- 支撑审计、回放、争议追踪和历史分析
- 与证据不可变和导出快照策略一致
- 满足等保和管理域要求

### Negative

- 存储成本持续增长
- 需要冷热分层、归档和索引治理
- 销毁流程必须非常严格

### Neutral

- 不改变前端职责
- 不改变服务域边界

## Compliance Impact

- 身份鉴别：查看历史和发起销毁都需严格鉴权
- 访问控制：按租户、角色、资源范围控制可见性
- 安全审计：归档、导出、销毁、恢复都必须留痕
- 加密存储：敏感字段和备份介质均加密
- 备份恢复：审计和元数据纳入优先恢复清单

## Implementation Notes

- 影响模块：公共管理服务、查询执行服务、导出和审计能力
- 需要冷热分层、归档任务、恢复流程与审批链
- 销毁策略必须通过独立任务和审计落地，不能直接物理删表

## Validation

- 单元测试：保留策略、销毁前校验、不可变结果控制
- 集成测试：审计归档、查询导出与恢复
- 构建验证：服务编译与任务契约测试
- 文档一致性检查：合规、部署和恢复文档一致
- 合规自检：`R-111` 至 `R-115` 场景检查
