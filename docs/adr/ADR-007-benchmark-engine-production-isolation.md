# ADR-007: 压测引擎与生产环境安全隔离策略

- Status: Accepted
- Date: 2026-04-19
- Deciders: Human Architect, Codex Implementation Lead
- Technical Story: `Phase-D / 压测引擎服务`
- Tags: benchmark, isolation, security

## Context

压测能力是 SQLForge 的核心功能之一，但架构文档明确要求压测引擎与生产环境物理隔离、只读优先且可审计。压测任务涉及高并发、阈值判定、资源占用和影子环境验证，不能污染生产数据源。

## Decision Drivers

- 压测任务可能产生高负载
- 规则要求当前边界不执行任意 SQL，并且未来读权限优先
- 压测必须可审计、可回放、可隔离
- 生产环境稳定性优先于压测便利性

## Considered Options

1. 压测直接跑在生产环境
2. 压测与生产共享同一资源池但逻辑隔离
3. 压测服务独立资源池，默认影子/隔离环境，只读执行

## Decision

选择压测引擎独立资源池并与生产环境隔离部署。压测默认只读、影子环境优先，访问生产环境前必须满足额外审批和审计要求；当前基线不允许直接对生产执行任意 SQL 压测。

## Consequences

### Positive

- 降低压测污染生产的风险
- 便于独立扩缩容和资源治理
- 满足安全与合规要求

### Negative

- 需要维护独立环境和数据准备链路
- 测试数据和生产真实负载之间可能存在偏差
- 报告解释需要明确样本环境

### Neutral

- 不改变查询执行服务和优化服务的主职责
- 不影响审计要求，反而强化了审计链路

## Compliance Impact

- 身份鉴别：压测提交与报告访问都要鉴权
- 访问控制：仅授权用户可提交压测且范围受数据源授权限制
- 安全审计：任务提交、取消、执行、阈值失败、报告导出全部留痕
- 加密存储：压测连接信息复用加密存储方案
- 备份恢复：压测报告和关键元数据纳入恢复清单

## Implementation Notes

- 影响模块：压测引擎服务、公共管理服务
- 压测任务模型必须显式包含只读标记、影子环境标记、脱敏要求
- 需要与调度、审计、报告导出联动

## Validation

- 单元测试：只读约束、阈值判断、状态流转
- 集成测试：隔离环境任务执行与报告生成
- 构建验证：服务编译与任务契约测试
- 文档一致性检查：接口契约、合规文档和部署文档一致
- 合规自检：压测越权、写操作与跨租户访问被拒绝
