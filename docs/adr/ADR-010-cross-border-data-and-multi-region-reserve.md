# ADR-010: 跨境数据流动与多区域扩展预留

- Status: Proposed
- Date: 2026-04-19
- Deciders: Human Architect, Codex Implementation Lead
- Technical Story: `Phase-F / 多区域扩展预研`
- Tags: multi-region, compliance, proposed

## Context

架构文档显示项目当前以单区域、华为云私有云起步，但生命周期预期为长期演进，后续可能扩展到多区域。该能力尚未成为当前阶段必须交付项，因此保持 Proposed 状态。

## Decision Drivers

- 当前目标环境是单区域优先
- 未来可能存在跨区域或跨境数据流动诉求
- 合规和数据主权风险高，不能提前假定已允许
- 当前阶段应避免过度设计，但需保留扩展位

## Considered Options

1. 当前阶段直接做多区域主动-主动
2. 当前阶段完全忽略多区域预留
3. 当前阶段保持单区域交付，同时预留租户、配置、审计和数据分层的扩展位

## Decision

提议选择“单区域优先，显式预留扩展位”的方案：

- 当前交付仍以单区域为准
- 在租户、配置、审计、导出、备份和部署模型中预留区域维度
- 跨境/多区域真正落地前，必须新增或升级 ADR，并完成专门合规评审

## Consequences

### Positive

- 避免当前阶段过度实现
- 为未来扩展保留结构化入口
- 降低后续大规模返工概率

### Negative

- 需要在当前设计中维护少量未来预留字段和文档说明
- 某些实现会多出扩展位但暂不启用

### Neutral

- 不影响当前单区域上线目标
- 不改变 4 微服务目标

## Compliance Impact

- 身份鉴别：跨区域身份联邦方案暂不落地
- 访问控制：当前仍以单区域租户隔离为准
- 安全审计：未来跨区域审计聚合需单独设计
- 加密存储：跨境数据和密钥管理需后续专门评审
- 备份恢复：当前仍以单区域备份恢复目标为准

## Implementation Notes

- 影响模块：部署、租户配置、审计归档、导出与备份
- 可预留 `region` 维度，但默认不启用跨区域复制
- 真正实施前需要补充网络、密钥、数据主权与灾备 ADR

## Validation

- 单元测试：预留字段不影响当前行为
- 集成测试：单区域部署行为不退化
- 构建验证：编译与部署文档检查
- 文档一致性检查：部署和合规说明明确区分“当前”与“预留”
- 合规自检：不提前承诺未评审的跨境能力
