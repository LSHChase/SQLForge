# ADR-011: 缓存一致性策略（Hudi 时间戳校验）

- Status: Accepted
- Date: 2026-04-19
- Deciders: Human Architect, Codex Implementation Lead
- Technical Story: `Phase-D / 查询执行服务`
- Tags: cache, consistency, hudi

## Context

项目需要在联机查询性能和数据一致性之间取得平衡。架构文档明确“数据一致性”是最高优先级质量属性之一，并给出缓存命中率、无脏读和 Hudi 作为数据湖存储的背景。

## Decision Drivers

- 数据一致性优先于纯性能
- 查询缓存必须与数据湖更新状态协同
- BI 场景对结果可信度敏感
- 需要可审计、可解释的缓存命中与失效逻辑

## Considered Options

1. 基于固定 TTL 的简单缓存
2. 完全不做缓存
3. 基于 Hudi 时间戳/版本校验的缓存一致性策略

## Decision

选择基于 Hudi 时间戳或等效版本信息的缓存一致性策略。缓存命中前必须校验目标数据集的版本或更新时间窗口，只有版本一致时才返回缓存结果；否则执行重新查询并刷新缓存。

## Consequences

### Positive

- 降低脏读和陈旧结果风险
- 让缓存命中具备可解释性
- 与加速策略和历史结果关联更紧密

### Negative

- 需要维护额外版本信息和校验逻辑
- 命中率可能低于纯 TTL 缓存
- 对元数据同步能力有依赖

### Neutral

- 不改变消息抽象或访问控制本身
- 不替代查询结果审计和导出快照

## Compliance Impact

- 身份鉴别：缓存返回前仍需鉴权
- 访问控制：缓存键和命中结果需绑定租户与授权范围
- 安全审计：缓存命中、失效和刷新路径需留痕
- 加密存储：缓存中不得泄露敏感连接信息
- 备份恢复：缓存属于可重建层，不替代事实存储

## Implementation Notes

- 影响模块：查询执行服务、公共管理服务、加速能力
- 缓存键必须包含租户、SQL 指纹、数据源和版本维度
- 命中与失效日志要包含耗时、原因和版本信息摘要

## Validation

- 单元测试：版本命中、版本不一致、刷新路径
- 集成测试：数据更新后缓存失效与回源
- 构建验证：服务编译和缓存相关测试
- 文档一致性检查：缓存策略与加速/数据层文档一致
- 合规自检：跨租户缓存命中被禁止
