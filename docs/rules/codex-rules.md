# Codex Rules

本文件为 append-only 规则账本，当前版本从 `docs/architecture/init.md` 完整同步 `R-001` 至 `R-115`。

## 文档与治理

- `R-001`：每个独立 Task 完成后必须清理上下文，只保留 ADR 引用和任务结论。
- `R-002`：用户输入中涉及实现的约束必须抽取并永久固化。
- `R-003`：规则库维护机制本身也受规则约束，不能删除或篡改。
- `R-004`：初始部署完成后必须提醒补齐其他环境配置。
- `R-005`：编码前必须先确认前端技术栈。
- `R-006`：任务执行必须按固定顺序优先读文档，而不是依赖 prompt 和记忆。
- `R-007`：跨步骤、跨前后端、跨领域任务必须先建或更新执行计划。
- `R-008`：新的需求或方案文档入库后，必须先保存到 `docs/references/` 再拆分落地。
- `R-009`：长期规则、边界和设计方向必须进入追加式历史账本。
- `R-010`：可复用规则必须落到文档、测试或 lint。
- `R-011`：`AGENTS.md` 必须保持简短，长期知识放入 `docs/`。
- `R-012`：大模块默认交付流程是完成记录、commit、tag、tag 回写完成记录。
- `R-013`：验证前后必须切换上下文，隔离实现态和验证态。
- `R-014`：遵循低 token 原则，先搜再读且只读最小必要范围。
- `R-062`：执行时必须保留全部需求原文和人类提供的规范原文。

## 架构与工程硬约束

- `R-015`：前后端必须可独立构建和部署。
- `R-016`：前端固定 Vue 3 + JavaScript + CSS，后端固定 Java 8 + Spring Boot 2.x。
- `R-017`：文件统一 UTF-8/LF，运行与构建路径兼容 amd64 和 arm64。
- `R-018`：前端负责编排与预校验，后端是规则、编排、执行、持久化与审计的权威边界。
- `R-019`：关键领域判断不能长期留在前端状态里，后端必须重校验。
- `R-020`：新的跨域行为必须经过后端 service/controller 边界进入。
- `R-021`：后端至少具备接口层、dto、service、logic/impl、entity、dao/mapper、vo 等分层。
- `R-022`：后端包结构必须是“领域目录 + 分层子目录”。
- `R-061`：项目必须前后端分离、支持 ARM，前端轻量、后端可重且强制分层。
- `R-068`：保持高内聚低耦合，跨域通过 Service DTO 交互，禁止 Entity 直接跨服务传输。

## 前端与页面

- `R-023`：页面必须按上下文、当前任务、关键输入、运行状态、结果、历史、下一步的顺序组织。
- `R-024`：优先展示摘要、结论和建议，JSON 仅做下钻。
- `R-025`：多个核心流程不能继续堆在同一长页面中。
- `R-026`：常驻页面承载主流程，弹窗和抽屉只做编辑、确认、告警。
- `R-027`：页面应尽量利用完整视口，避免卡片套卡片。
- `R-028`：已交付后端能力必须在 operator 页面可见。
- `R-029`：历史 spec 或已完成计划中定义的页面能力未经人工批准不能移除。
- `R-030`：开发门户和业务主路径必须分离。

## 持久化、历史、导出、审计

- `R-031`：MySQL 是后续主持久化方向。
- `R-032`：浏览器本地状态不能作为历史查询或导出的唯一事实来源。
- `R-033`：历史对象必须支持后端查询、筛选、分页和导出。
- `R-034`：配置、结果、历史、导出、审计之间必须有可追溯关联键。
- `R-035`：密码、令牌等敏感信息禁止明文落库。
- `R-036`：完成结果是不可变证据，只允许注释、标签、归档、软删除类元数据控制。
- `R-037`：导出必须基于后端快照或可复现查询。
- `R-038`：历史默认永久保留，增长问题通过观测、分页、过滤解决。
- `R-039`：压测路径必须覆盖关键状态流转日志，且日志不得泄露敏感字段。

## 可靠性与安全

- `R-040`：结项前至少执行知识检查、后端测试、前端构建和文档代码一致性检查。
- `R-041`：HTTP handler 失败时必须返回明确 JSON 错误。
- `R-042`：相同输入应尽量产生确定性的 workflow 输出。
- `R-043`：MySQL 三种 repository mode 必须保持同样的 workflow 和 history 契约。
- `R-044`：影响 operator 的运行假设必须落到测试、日志、配置或文档。
- `R-045`：当前边界不执行任意 SQL，未来接入默认只读优先且影子测试必须可审计。
- `R-046`：transport 边界必须做 request 校验，tenant 身份必须显式化。
- `R-047`：每个新的外部 connector 都必须记录访问范围和安全边界。

## 产品级与冲突确认

- `R-048`：目标架构不能被当成已实现事实，已交付行为以当前实现文档为准。
- `R-049`：涉及删规则、改边界、废弃主存储或变更契约且有兼容风险的需求必须先记录影响并人工确认。
- `R-050`：冲突记录至少包含受影响范围、收益、破坏面、推荐方案和备选方案。
- `R-069`：项目总原则是轻前端、权威后端、MySQL 主持久化、后端负责历史导出审计、页面按任务流组织、规则必须文档化或工具化。

## 技术选型确认

- `R-051`：代码版本管理采用 GitHub Flow。
- `R-052`：开源协议采用 Apache License 2.0。
- `R-053`：文件编码必须为 UTF-8，行尾必须为 LF。
- `R-054`：前端技术栈采用 Element Plus + 自研组件。
- `R-055`：暂不引入数据库迁移工具，达到阈值时再评估 Flyway。
- `R-056`：API 版本控制以 `Accept-Version` Header 为主，URL 路径和参数为辅。
- `R-057`：错误码全局统一，系统级 `10000-19999`，业务级 `20000-29999`，再按服务域细分。
- `R-058`：Git 提交规范采用 Conventional Commits。
- `R-059`：暂不要求版权头模板。
- `R-060`：流程主要节点必须打印有效日志。
- `R-063`：前端样式方案是 Element Plus + 自研。

## 后端实现

- `R-064`：流程日志至少包含操作类型、实体标识、耗时和结果状态。
- `R-065`：数据访问层必须使用 MyBatis XML，禁止复杂 SQL 注解化。
- `R-066`：多环境配置必须通过 `application-{profile}.yml` 区分，禁止硬编码。
- `R-067`：Utils、Constants、Exception、Audit、Async、Redis 等必须抽为公共层。
- `R-070`：仓库根目录必须存在 `.gitignore` 并忽略 IDE、编译输出、敏感配置和日志。
- `R-071`：仓库根目录必须存在 `.editorconfig` 并定义 UTF-8、LF 与前后端缩进。
- `R-072`：仓库根目录必须存在 Apache 2.0 完整 `LICENSE`。
- `R-073`：仓库根目录必须存在 `README.md` 作为文档入口。
- `R-074`：仓库根目录必须存在简短且指向 `docs/` 的 `AGENTS.md`。
- `R-075`：必须存在 `.github/workflows/ci.yml`。
- `R-076`：必须存在 `docker-compose.yml`，编排 MySQL、Redis、Kafka、MinIO。
- `R-077`：必须存在 `Makefile` 或 `scripts/build.sh`，提供标准化命令。
- `R-078`：后端必须存在父 POM 统一管理依赖版本。
- `R-079`：必须存在主配置 `application.yml`。
- `R-080`：必须存在开发配置 `application-dev.yml`。
- `R-081`：必须存在测试配置 `application-test.yml`。
- `R-082`：必须存在生产配置 `application-prod.yml`。
- `R-083`：必须存在 `logback-spring.xml`，支持控制台、滚动文件、JSON 和脱敏。
- `R-084`：必须存在 `mybatis-config.xml`。
- `R-085`：必须存在测试资源配置。
- `R-086`：必须存在代码质量检查配置。
- `R-087`：必须存在 `lombok.config`。

- `R-089`：必须存在 `vite.config.js` 并配置端口、代理、Element Plus 按需导入和 ARM64 兼容。
- `R-090`：必须存在 `.eslintrc.js` 且基于 Element Plus 推荐配置。
- `R-091`：必须存在 `.prettierrc`。
- `R-092`：必须存在前端入口 `src/main.js`。
- `R-093`：必须存在根组件 `src/App.vue`。
- `R-094`：必须存在路由文件 `src/router/index.js`。
- `R-095`：必须存在 Pinia 配置 `src/stores/index.js`。
- `R-096`：必须存在 `src/locales/zh-CN.js` 和 `src/locales/en-US.js`。
- `R-097`：必须存在主题变量文件 `src/styles/element-plus-theme.css`。
- `R-098`：必须存在前端模板 `index.html`。

- `R-100`：必须存在 `docs/references/human-constraint-history.md`。
- `R-101`：必须存在空目录 `docs/references/raw-requirements/`。
- `R-102`：必须存在 `docs/adr/README.md`。

## 部署与数据初始化

- `R-106`：必须存在 `sql/init-schema.sql` 初始化表结构。
- `R-107`：必须存在 `sql/init-data.sql` 初始化基础数据。
- `R-108`：初始部署完成后必须提醒独立部署 MySQL 环境。
- `R-109`：必须存在 `docs/deployments/local-setup.md` 本地搭建指南。
- `R-110`：必须存在 `docs/deployments/huawei-cloud-setup.md` 华为云部署指南。

## 等保合规

- `R-111`：所有用户操作必须经过后端身份鉴别，管理员与普通用户权限分离。
- `R-112`：必须基于租户 ID 做访问控制与数据隔离，禁止越权查询。
- `R-113`：所有 SQL 操作、登录登出、权限变更必须进入审计日志，保留不少于 180 天且不可改删。
- `R-114`：数据库密码、API 密钥等敏感配置必须加密存储，禁止明文落库。
- `R-115`：MySQL 必须具备主从复制和定期全量备份，满足 `RPO < 1小时`、`RTO < 4小时` 且备份加密。
