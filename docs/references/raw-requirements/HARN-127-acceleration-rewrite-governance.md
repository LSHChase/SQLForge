# HARN-127 Raw Requirement Snapshot

## Source

- Date: 2026-05-10
- Task: HARN-127
- Type: user-provided design and task-shaping requirement

## User Requirement Excerpts

用户要求参考另一个 Codex 窗口的历史内容，继续完成加速功能子流程复盘，并且先做设计不实现。历史输入重点包括：

```text
作为一名资深架构设计师，深入分析下这个流程实现了没，是否有偏离，是否真实可测试，并优化下这个流程，给我输出优化后的流程详情，先不实现，先做设计，顺便包含一个可以调用真实接口模拟测试流程的页面设计。
```

用户随后追加要求：

```text
模拟测试页面设计如有已经实现的页面功能，可以跳转，只在模拟测试页面增加流程图，如未实现或无页面，可在这个页面做简单的测试功能，另外页面设计有点不太符合设计规范；解析驱动与查询驱动就两条入口吧，但是后的加速候选、计划审批、应用验证需要展示在同一个页面，且有个字段说明是解析的还是查询的；另外，推荐的sql那边的逻辑上好像不太深入，深度不够，只有简单的逻辑，这个需要细化；推荐前后的sql要在页面上能对比出差异；另外还有个需求，改写记录应该在sql历史查询页面上能够看到记录；要定期对改写前后的sql结果做比对，如发现结果有差异，需要监控告警。作为一名资深架构设计师，对以上内容全面严格分析，不要丢失内容，然后给出优化后的方案。
```

本轮用户明确要求：

```text
好的，再复盘下历史记录，如果有丢失的内容需要加入这个方案的，直接加入，然后把完整方案落地到本地的doc中。然后作为一名资深的架构设计师和前端设计师，你什么擅长harness engineering原理和codex，将这个方案拆成codex推荐能执行不出偏差的任务清单，不要偷懒，严格模式下将完整方案的全部拆分小任务，然后将任务落地，后续我将按照选取每个任务，然后按/plan完善后执行实现。
```

## Normalized Scope

- 只落地设计文档和后续任务清单，不实现业务代码。
- 复盘历史方案，补齐遗漏点。
- 保持解析驱动与查询驱动两条入口。
- 后续加速候选、计划审批、应用验证和监控告警在统一工作台页面展示。
- 已有页面能力只跳转复用；缺失操作在工作台提供轻量真实接口测试按钮。
- 推荐 SQL 逻辑要深化，并展示推荐前后 SQL 差异。
- SQL 历史必须能看到改写记录。
- 改写前后结果必须定期比对，发现差异时监控告警。
- 按 Harness Engineering 和 Codex 可执行性拆小任务，后续由用户逐个选择并 `/plan`。
