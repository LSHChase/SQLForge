# SQL生命周期治理平台 — 架构初始化总文档

**版本：** v1.0.0-Final  
**遵循：** Harness Engineering / MADR / Conventional Commits / GitHub Flow  
**目标受众：** 人类架构师（决策层） + Codex（实现层）  
**总规则数：** R-001 至 R-115  
**ADR数量：** ADR-001 至 ADR-013  

---

## 第一部分：项目战略与元数据

### 1.1 业务域与价值主张

**业务域：** 大数据分析平台 + BI领域 + 数据中台  

**核心价值：** 为企业BI用户提供从SQL设计、优化、压测到执行的全生命周期治理平台，解决SQL性能、分流与治理问题，支撑百亿级日增数据下的查询性能与数据一致性。

**一句话价值主张：** 让每一条BI SQL在上线前经过解析、压测、改写、路由与加速的全链路治理，确保生产环境查询性能可预期、数据一致可信赖。

### 1.2 组织上下文

| 维度 | 内容 |
|:---|:---|
| 团队规模 | 13人（1前端、5后端、2运维、3测试、2产品经理） |
| 技术成熟度 | 中等（熟悉Java生态，分布式经验中等，借助开源基座自研核心引擎） |
| 生命周期预期 | 长期演进（单区域起步，后期扩展至多区域） |
| 存量系统 | 已有自研执行引擎，本项目为增强型治理平台 |

### 1.3 康威定律映射

13人团队采用微服务架构，遵循"2 Pizza Team"原则：每个服务域由1-2名后端负责。运维2人负责华为云基础设施与中间件维护，测试3人覆盖集成测试与压测验证。

## 第二部分：架构总原则与规则库（R-001 至 R-115）

### 2.1 Harness Engineering核心原则

**人类负责意图、约束与决策；Codex负责实现与代码生成。** 所有意图必须在编码前以文字契约固化，禁止在实现阶段追加业务逻辑变更。

## 第四部分：业务流程架构（完整版）

### 4.1 联机查询主流程（实时路径）

**触发条件：** BI工具或用户界面提交查询请求

**执行步骤：**
1. **请求接入：** 用户提交SQL文本与上下文参数（租户ID、数据源类型、会话变量）
2. **合规检查：** 自动触发敏感数据识别、权限校验、SQL注入检测；高风险SQL拦截，中风险标记复核，低风险放行
3. **缓存检查：** 基于SQL指纹与参数哈希查询结果缓存
   - 缓存命中：校验Hudi时间戳与数据新鲜度，有效则直接返回
   - 缓存未命中：进入路由决策
4. **智能路由：** 基于SQL复杂度评分、引擎负载、租户配置选择目标引擎（Hetu/Hive/Spark/ClickHouse）
5. **轻量解析：** 生成AST摘要（表名、列名、操作类型、复杂度评分），耗时<50ms
6. **轻量改写：** 应用简单规则（分区裁剪、limit下推），不影响查询效率
7. **执行引擎调用：** 通过Hetu（JDBC/REST/客户端）、Hive、Spark或ClickHouse执行
8. **结果返回：** 流式返回查询结果
9. **异步后置：**
   - 审计事件写入：Kafka/消息链路仅作异步缓冲、补偿与重试，短期保留；权威审计日志主存储落库后保留不少于180天
   - 查询记录落库（MySQL）
   - 触发异步深度解析任务（首次或Schema变更时）
   - 触发异步加速分析任务（识别加速机会）

**合规嵌入点：** 步骤2（事前审核）、步骤9（审计留痕）

### 4.2 异步优化子流程（离线路径）

**触发条件：** 设计阶段保存SQL、定时扫描、数据Schema变更事件

**执行步骤：**
1. 任务调度服务获取待解析SQL任务
2. 深度解析：基于Apache Calcite + Druid Parser + Presto Parser融合引擎，生成完整AST
3. 规则引擎改写：应用100+优化规则（子查询转Join、聚合下推、物化视图匹配）
4. AI推荐改写：基于历史执行数据与成本模型，推荐更优SQL写法
5. 结果反馈：
   - 推荐：展示改写后SQL与预期收益
   - 不推荐：说明当前SQL已达较优状态
   - 风险提示：标记潜在全表扫描、笛卡尔积等风险
6. 异步落库：解析记录、改写建议、审计日志

### 4.3 压测评估子流程（基线路径）

**触发条件：** 用户完成SQL设计并保存、数据量显著变化（自动探测）、周期性夜间低峰执行

**执行步骤：**
1. 压测任务进入调度队列（租户资源隔离）
2. 压测引擎基于JMeter核心 + Gatling并发模型 + sysbench统计方法自研实现
3. 多引擎并行压测：同一SQL在Hetu、Hive、Spark、ClickHouse分别执行
4. 性能基线生成：收集QPS、P50/P99延迟、CPU/内存占用、扫描数据量
5. 阈值判定：
   - 通过：加入路由候选集，允许发布
   - 警告：允许发布但标记风险，推荐优化
   - 失败：禁止发布，强制优化
6. 报告生成：反馈业务方与技术方，包含对比图表与优化建议

**日志要求（R-039）：** 必须覆盖task接收、campaign/stage/run状态流转、gate、取消、失败；禁止携带密码等敏感字段。

### 4.4 加速功能子流程（新增独立能力）

**功能定位：** 对联机SQL分析后的性能优化操作，独立于路由与改写，作为可选增强能力。

**触发条件：**
- SQL发布前，用户主动申请加速
- 系统识别到SQL性能瓶颈（P99延迟超过阈值或扫描数据量过大）
- 数据模型变更后，已有加速配置失效

**加速操作类型：**
1. **预计算：** 将高频聚合查询结果预计算为物化视图，定时刷新
2. **分区优化：** 推荐或自动调整表分区策略（按时间/业务键），减少扫描范围
3. **分桶优化：** 对Join键进行分桶（Bucket），减少Shuffle
4. **拆分优化：** 将大SQL拆分为多个小SQL并行执行，结果聚合返回
5. **替换优化：** 推荐等价但性能更优的SQL写法（如用Window Function替代自连接）

**执行步骤：**
1. 加速建议生成：基于SQL解析结果与数据特征，生成加速建议清单
2. 用户确认：展示每项加速操作的预期收益与成本（存储增加、刷新延迟）
3. 加速配置生效：将配置写入元数据服务，关联到SQL指纹
4. 执行拦截：后续相同SQL查询时，自动应用加速配置（改写SQL或路由到预计算结果）
5. 效果监控：跟踪加速后的延迟与资源占用，失效时自动告警

**状态管理：**
- 草稿：建议生成，待用户确认
- 生效：已应用，监控中
- 失效：数据变更导致配置失效，需重新评估
- 废弃：用户手动取消或系统判定收益为负

### 4.5 异常回滚流程（新增详细设计）

**触发条件：** 联机查询主流程中任意环节失败

**回滚策略：** 先重试，后降级，最后返回错误

**详细流程：**

| 失败环节 | 重试策略 | 降级策略 | 最终处理 |
|:---|:---|:---|:---|
| **缓存读取失败** | Redis连接超时重试1次 | 跳过缓存，直接走主流程 | 记录缓存异常，不影响查询 |
| **路由决策失败** | 重新获取元数据，重试1次 | 降级到默认引擎（租户配置中的默认引擎） | 返回错误，标记路由异常 |
| **轻量解析失败** | 切换备用解析器（Druid/Presto），重试1次 | 标记为未知复杂度，直接提交执行 | 记录解析异常，异步深度解析 |
| **引擎执行失败** | 同一引擎重试1次（网络抖动） | 切换到次优引擎（路由规则中的备用引擎） | 返回错误，记录执行异常 |
| **Hetu连接失败** | JDBC模式失败后尝试REST模式 | 切换到Hive或Spark（延迟容忍场景） | 返回错误，告警通知 |
| **结果返回超时** | 延长等待时间（流式结果） | 返回已获取部分结果，标记不完整 | 记录超时，触发异步补全 |

**补偿机制：**
- 执行失败但已产生部分副作用（如临时表、锁）时，执行清理任务
- 审计日志必须记录完整的重试与降级路径
- 降级到备用引擎时，需在返回结果中标记"降级模式"，提示用户

### 4.6 合规与审计流程（贯穿层）

**执行步骤：**
1. SQL提交后立即进入合规检查点
2. 自动审核：
   - 敏感数据识别（基于正则+语义分析）
   - 权限校验（租户数据范围、表级权限、列级脱敏）
   - 规则拦截（禁止DDL、限制返回行数、禁止无where条件）
3. 分级处置：
   - 低风险：自动放行，记录审计日志
   - 中风险：标记待人工复核
   - 高风险：立即拦截，返回明确拒绝原因
4. 审计日志双写：本地MySQL事务落盘 + Kafka异步发送（失败补偿重试）

**等保合规嵌入（R-111至R-115）：**
- 身份鉴别：步骤1校验租户Token与权限
- 访问控制：步骤2校验数据源访问权限
- 安全审计：步骤4双写审计日志，保留180天+
- 数据完整性：敏感配置加密传输与存储
- 备份恢复：审计日志表独立备份策略

### 5.3 核心接口契约

#### 5.3.1 查询执行服务接口

**接口名称：** 联机SQL查询执行

**调用方式：** HTTP POST，同步返回结果，异步记录日志

**输入契约：**
- 原始SQL文本：字符串，最大长度10MB
- 租户标识：字符串，UUID格式，用于权限与方言识别
- 数据源类型枚举：HETU / HIVE / SPARK / CLICKHOUSE / GAUSSDB / AUTO（自动路由）
- 查询上下文：可选，包含数据库名、Schema版本、会话变量、超时时间
- 加速偏好：可选枚举，PREFER_ACCELERATED（优先加速）/ PREFER_FRESH（优先新鲜度）/ NONE（无偏好）
- 容错策略：可选枚举，RETRY_THEN_FALLBACK（先重试后降级）/ FAIL_FAST（快速失败）/ FALLBACK_IMMEDIATE（立即降级）

**输出契约：**
- 查询状态：SUCCESS / PARTIAL（降级模式）/ FAILED / TIMEOUT
- 结果数据：JSON数组或流式下载链接，最大返回行数受租户配额限制
- 执行元数据：目标引擎、实际执行SQL（改写后）、执行耗时、扫描行数、缓存命中标记、加速配置应用标记
- 降级标记：布尔值，若使用了备用引擎或部分结果，标记为true并附原因（原引擎失败/超时/连接不可用）
- 重试路径：数组，记录重试的引擎序列与每次耗时
- 错误详情：状态为FAILED时返回，包含错误码、错误消息、建议操作、可重试标记

**边界条件：**
- 超时控制：默认30秒，可配置，超时时返回已获取部分结果（如适用）
- 行数限制：超过租户配额时截断并标记"结果截断"
- 敏感数据：自动脱敏，审计日志记录脱敏标记
- 异常回滚：路由失败时自动重试备用引擎，执行失败时清理临时资源（临时表、锁、连接）

**接口名称：** 异步解析任务提交（供SQL优化服务回调）

**调用方式：** HTTP POST，异步返回任务ID

**输入契约：**
- SQL指纹：字符串，MD5哈希
- 解析深度：LIGHT / DEEP
- 优先级：HIGH（用户等待）/ NORMAL（后台）/ LOW（定时）
- 回调URL：可选，解析完成后通知地址

**输出契约：**
- 任务ID：UUID
- 预计完成时间：基于队列长度估算
- 状态查询地址：HTTP GET路径

## 变化说明

### 服务合并映射

| 原服务 | 合并后服务 | 合并理由 |
|:---|:---|:---|
| 查询网关服务 + SQL解析服务（轻量）+ SQL改写服务（轻量）+ 执行管理服务 + 加速服务（应用层） | **查询执行服务** | 联机查询主流程需端到端低延迟，合并减少RPC；解析与改写轻量路径内嵌，加速配置在路由后应用 |
| SQL解析服务（异步深度）+ SQL改写服务（异步）+ 加速服务（核心建议生成）+ 元数据服务（优化相关） | **SQL优化服务** | 异步优化逻辑内聚，共享AST分析与成本模型；物化视图管理作为独立子域 |
| 压测引擎服务 + 任务调度服务（压测相关） | **压测引擎服务** | 压测需独立资源池，调度逻辑内嵌；保持与生产环境隔离 |
| 平台治理服务 + 元数据服务（管理部分）+ 合规审计服务 + 数据血缘服务 + 任务调度服务（通用部分） | **公共管理服务** | 管理面功能内聚，共享租户上下文与审计基础设施；血缘服务作为独立子模块可扩缩容 |

### 关键调整点

1. **查询执行服务** 成为核心入口，承担原网关+解析+改写+执行+加速应用的全链路，确保联机查询P99<50ms目标不受RPC损耗影响
2. **SQL优化服务** 独立部署，避免异步计算影响联机查询；与查询执行服务通过接口交互，推送加速配置
3. **压测引擎服务** 保持独立隔离，确保压测不污染生产
4. **公共管理服务** 作为管理面底座，提供租户、配置、审计、血缘等共享能力；血缘计算密集型特性通过子模块独立扩缩容解决

### 接口契约调整

- 新增查询执行服务与SQL优化服务间的异步任务回调接口
- 新增公共管理服务的通用任务调度接口（替代原独立任务调度服务）
- 压测引擎服务接口简化，移除与通用调度的耦合
- 所有服务间调用明确通过HTTP REST，避免直接数据库共享（公共管理服务除外，作为数据底座）

### 6.2 分层调用规则（强制）

| 规则 | 说明 | 违反后果 |
|:---|:---|:---|
| 上层可调下层，下层不可调上层 | controller→service→domain→infrastructure | 循环依赖 |
| 同层不可直接调用 | domain内子域间通过service编排 | 领域耦合 |
| 跨服务通过DTO交互 | 禁止直接传递Entity | 边界侵蚀 |
| 领域层无Spring注解 | 纯POJO + 逻辑实现，依赖注入在service层 | 框架污染 |

### 6.3 多环境配置策略

- `application.yml`：公共配置（服务名、端口、日志级别、Actuator）
- `application-dev.yml`：本地开发（Docker Compose服务地址、H2可选、调试日志）
- `application-test.yml`：测试环境（测试集群地址、连接池优化）
- `application-prod.yml`：生产环境（TDSQL/GaussDB、Redis集群、Kafka集群、连接池生产参数、JSON日志）

**激活方式：** Spring Profiles，通过启动参数或环境变量指定，禁止代码硬编码环境判断。

### 6.4 公共组件抽取（高内聚低耦合）

| 组件包 | 职责 | 实现要求 |
|:---|:---|:---|
| **utils** | 通用工具方法 | 静态方法，无状态，线程安全；禁止依赖Spring容器 |
| **constants** | 枚举与常量 | 错误码、缓存Key前缀、数据源类型、状态枚举 |
| **exception** | 异常体系 | 业务异常与系统异常分层；全局异常处理器统一返回JSON错误 |
| **audit** | 审计上下文 | ThreadLocal传递操作人、租户ID、请求链路ID |
| **async** | 异步执行 | 基于Spring Async封装线程池，支持租户隔离的异步任务 |
| **log** | 流程日志 | 注解式日志打印，主要节点必须打印有效日志 |

### 6.5 数据访问策略

- **ORM框架：** MyBatis（XML配置方式，禁止复杂SQL用注解）
- **事务管理：** 本地事务为主，@Transactional在Service层入口
- **多数据源：** 动态数据源切换支持不同租户或引擎连接池

- 属性：规则ID、规则名称、优先级、匹配条件（SQL特征）、目标引擎、备用引擎、权重、状态（草稿/生效/禁用/废弃）

**AccelerationConfig（加速配置实体，新增）：**
- 属性：配置ID、SQL指纹、加速类型（预计算/分区/分桶/拆分/替换）、配置详情JSON、生效状态（草稿/生效/失效/废弃）、创建时间、失效时间
- 关联：多个MaterializedView（物化视图）、多个PartitionStrategy

**TenantConfig（租户配置实体）：**
- 属性：租户ID、配额（并发数/存储量/查询次数）、默认引擎、备用引擎、SQL审核级别、数据保留天数、加速配额

## 第十一部分：Codex拆解规范与规则库

### 11.1 任务拆解三层模型

| 层级 | 定义 | 交付物 | 工时估算 |
|:---|:---|:---|:---|
| **Epic** | 完整服务域交付 | 可部署的服务包 + 接口文档 + ADR | 2-3周 |
| **Story** | 单一接口或核心机制 | 可独立测试的功能模块 + 单元测试 | 2-3天 |
| **Task** | Codex最小生成单元 | 单一函数/配置/类 + 测试用例 | 2-4小时 |

### 11.2 Codex输入模板（每个Task必须包含）

1. **任务ID与名称**
2. **关联ADR编号**
3. **关联规则编号**（如R-021、R-060）
4. **上下文引用：** 需读取的文档路径（按R-006顺序）
5. **接口契约：** 输入/输出/边界条件纯文字描述
6. **技术约束：** Java 8、Spring Boot 2.x、MyBatis XML、Element Plus等
7. **分层定位：** controller/service/domain/infrastructure/common
8. **测试策略：** 正常/异常/边界场景
9. **依赖声明：** 前置Task
10. **环境要求：** dev/test/prod配置差异

### 11.3 Codex执行步骤（详细指令）

**步骤1：环境准备**
- 读取 `docs/README.md` 确认文档地图
- 读取 `docs/architecture/init.md`（本文档）确认架构总览
- 读取 `docs/rules/codex-rules.md` 确认当前规则库
- 检查本地Git仓库状态，确保在main分支且工作区干净

**步骤2：任务接收与解析**
- 接收人类输入的任务描述
- 识别任务中的强约束词（"必须"、"禁止"、"要求"等），提取为规则追加到R-002
- 将原始需求原文保存到 `docs/references/raw-requirements/{timestamp}-task.md`
- 确定任务层级（Epic/Story/Task）

**步骤3：计划与依赖检查**
- 如果是Epic或跨域Story，先创建或更新 `docs/plans/{plan-name}.md`
- 检查前置依赖Task是否已完成（状态为"已完成"）
- 若依赖未完成，标记当前任务为"已阻塞"，返回阻塞原因

**步骤4：文档读取（低Token原则）**
- 按R-006顺序读取必要文档，只读最小必要范围
- 读取关联ADR确认技术决策边界
- 读取关联接口契约确认输入输出

**步骤5：代码生成（分层约束）**
- 严格按R-021/R-022分层生成代码
- 领域层禁止Spring注解，纯POJO
- MyBatis SQL必须写在XML中（R-065）
- 主要节点添加日志打印（R-060/R-064）
- 敏感信息处理符合R-035/R-114

**步骤6：测试生成**
- 单元测试覆盖核心业务逻辑（100%）
- 包含正常、异常、边界场景
- 测试资源配置使用 `application-test.yml`

**步骤7：质量自检**
- 运行 `scripts/lint-repository-knowledge.js` 检查文档完整性
- 运行后端测试
- 运行前端构建（如涉及）
- 检查ADR引用完整性

**步骤8：上下文清理（R-001）**
- 任务完成后，清理实现阶段上下文
- 仅保留：ADR引用、规则引用、任务结论、生成的文件清单
- 准备进入验证阶段

**步骤9：验证与交付**
- 上下文切换至验证模式（R-013）
- 人类验收或自动化验收
- 通过后：完成记录 → Commit（Conventional Commits，R-058） → Tag → 回写Tag至完成记录（R-012）
- 若用户阻止Git操作，仅更新完成记录

**步骤10：规则固化与提醒**
- 将任务中识别的新规则追加到 `docs/rules/codex-rules.md`
- 更新 `docs/references/human-constraint-history.md`
- 如果是初始部署完成，提醒进行MySQL独立环境部署（R-004/R-108）

### 15.2 日志规范

**主要节点强制打印日志：**

**禁止：** 日志中打印密码、Token、SQL完整文本（需脱敏或摘要）。

| 100PB存储成本超预算 | 架构重构 | 冷热分层自动化；OBS归档压缩；Hudi小文件合并 |
| Hetu与自研路由兼容性问题 | 查询失败 | ADR-004定义三模式回退；JDBC保底 |
| 团队分布式经验不足 | 微服务治理混乱 | 阶段0强化脚手架与规范；Code Review强制检查分层合规 |
| 多租户资源争抢 | 服务质量下降 | 平台治理服务实现配额硬限制；Sentinel限流熔断 |
| 前端Element Plus定制过深 | 升级困难 | 自研组件基于Element Plus二次封装，保留升级空间 |
| 加速配置失效导致查询失败 | 可用性下降 | 加速配置独立校验，失效时自动回退到非加速路径 |
| 等保合规遗漏 | 法律风险 | 阶段0即嵌入R-111至R-115，阶段3专项自检 |
