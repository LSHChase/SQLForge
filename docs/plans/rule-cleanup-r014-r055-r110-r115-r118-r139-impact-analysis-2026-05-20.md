## Core Impact Details

### `R-111` 身份鉴别

问题：

- 直接删除会让受保护 API、跨服务内部请求、角色模型和登录/登出审计失去统一前置条件。
- 前端隐藏页面不能替代后端身份校验。

解决方案：

- 推荐方案 A：保留最小身份鉴别内核，只清理产品化页面或公开辅助治理面解释。
- 备选方案 B：若要降低到内网 demo 模式，必须新增显式 profile / feature flag，并确保生产默认仍启用。
- 不推荐方案 C：删除身份鉴别规则。该方案会破坏核心安全边界，必须由人类明确接受风险后才能实施。

### `R-112` 访问控制

问题：

- 删除或弱化会影响租户隔离、数据源授权、查询执行、SQL 优化、压测和开放接入。
- fail-open 会使未授权 SQL 查询或跨租户历史读取成为可能。

解决方案：

- 推荐方案 A：保留默认拒绝和统一授权入口，清理旧的产品化治理入口表述。
- 备选方案 B：把 demo 数据和真实数据源访问拆成不同 profile，但生产 profile 不得绕过授权。
- 不推荐方案 C：取消租户/数据源授权。该方案需要人工确认。

### `R-113` 安全审计

问题：

- SQL 执行历史、真实改写历史、runtime binding `ACTIVE` 证据和失败补偿链都依赖最小审计/历史留痕。
- 直接 drop 审计要求会让“执行过什么、为何改写、如何回放问题”不可追踪。

解决方案：

- 推荐方案 A：保留最小审计事件、执行历史和改写历史；不恢复审计取证产品页和公开 trace API。
- 备选方案 B：缩小审计范围，但必须列出保留事件类型、保留周期和历史兼容策略。
- 不推荐方案 C：删除审计留痕。该方案需要人工确认。

### `R-114` 加密存储

问题：

- 直接删除会允许数据库密码、Token、API key 等明文落库或出现在日志/导出。
- 现有 schema、migration、共享加密组件和持久化入口已经围绕密文字段建立。

解决方案：

- 推荐方案 A：保留敏感字段加密和日志脱敏；只清理不再需要的公开治理展示语义。
- 备选方案 B：更换算法或密钥管理方式，但需要迁移和回滚方案。
- 不推荐方案 C：取消加密。该方案需要人工确认。

### `R-115` 备份恢复

问题：

- 删除恢复目标会影响生产部署、审计链、核心元数据和外部环境恢复责任。
- 但恢复演练产品页已按执行引擎纯化方案移出默认产品面。

解决方案：

- 推荐方案 A：保留备份恢复 runbook、RPO/RTO 目标和生产责任边界；不恢复产品化恢复演练页面。
- 备选方案 B：降低 RPO/RTO 或只保留文档提示，需要生产 owner 明确接受。
- 不推荐方案 C：删除备份恢复要求。该方案需要人工确认。

### `R-118` 渐进合规验证

问题：

- 删除会让任务或阶段切换无法自动发现身份、访问控制、审计、加密、备份恢复退化。
- 旧描述容易被误读成要求恢复审计取证、告警中心、运行门禁页或恢复演练产品面。

解决方案：

- 推荐方案 A：保留 `R-118`，但把验证范围收口为最小执行安全合规基线。
- 备选方案 B：拆分为多个更窄验证规则，例如身份/授权、审计/历史、加密、备份文档。
- 不推荐方案 C：完全删除合规验证。该方案需要人工确认。

## Non-Core Cleanup Applied

- `R-014`：当前文档消费为效率提示，不再作为硬性验证锚点。
- `R-055`：当前持久化口径改为“无 Flyway 默认依赖 + SQL 增量脚本强制维护”。
- `R-110`：当前部署口径改为“华为云/私有云生产部署场景权威 runbook”，而不是所有任务的通用阻断项。
- `R-139`：当前阶段切换不依赖聊天语义自动触发，只由显式标准动作和 workflow 触发。

## Human Decision Required

`R-111` 至 `R-115` 与 `R-118` 的破坏性删除或弱化会影响核心安全、核心历史证据或生产恢复边界，已转入 `INBOX-008` 等待人类决定。推荐选择：

- A：保留最小执行安全内核，只清理产品化辅助治理面解释。
- B：将 `R-111` 至 `R-115` / `R-118` 重写为更窄的执行引擎安全规则，但必须保留身份、租户、历史、加密、备份和验证替代项。
- C：删除或大幅弱化上述核心规则。该方案会产生明确安全与审计风险，不建议默认执行。
